# Code of Conduct

## Our Pledge

We are committed to making participation in WaysNX UI Kit a welcoming, respectful, and constructive experience for everyone.

We expect contributors, maintainers, reviewers, and other participants to interact professionally and respectfully regardless of background, experience level, or role in the project.

---

## Expected Behavior

Participants are expected to:

- Be respectful and professional.
- Communicate constructively.
- Focus discussions on the work and the problem being solved.
- Welcome different technical perspectives.
- Give and receive constructive feedback.
- Assume good intent while addressing disagreements directly.
- Respect project decisions and established contribution processes.
- Avoid behavior that could reasonably make another participant feel unsafe, unwelcome, or harassed.

---

## Unacceptable Behavior

The following behavior is not acceptable:

- Harassment, intimidation, or discrimination.
- Personal attacks or insults.
- Threats or deliberately hostile behavior.
- Sexualized language or unwanted sexual attention.
- Publishing private or personally identifying information without permission.
- Trolling, deliberately disruptive behavior, or sustained bad-faith participation.
- Unwelcome contact outside the project.
- Other conduct that would reasonably be considered inappropriate in a professional open-source community.

---

## Technical Disagreements

Technical disagreement is expected in an engineering project.

Participants are encouraged to challenge:

- Design decisions
- Architecture
- APIs
- Implementation approaches
- Testing strategies
- Documentation
- Performance considerations

Disagreement should remain focused on the technical issue rather than the person proposing the change.

Maintainers may make the final decision when consensus cannot be reached.

---

## Maintainer Responsibilities

Project maintainers are responsible for maintaining a professional and constructive project environment.

Maintainers may:

- Request changes to inappropriate discussions or contributions.
- Close discussions that become disruptive.
- Remove content that violates this Code of Conduct.
- Temporarily or permanently restrict participation when necessary.
- Escalate serious incidents to appropriate channels.

Maintainer actions should be proportionate to the behavior and the circumstances.

---

## Reporting

If you experience or observe behavior that violates this Code of Conduct, report it privately to the project maintainers.

**Do not use public GitHub issues for sensitive conduct reports.**

For security vulnerabilities, use the process described in [SECURITY.md](SECURITY.md).

When reporting a conduct issue, provide:

- A description of the incident.
- The relevant project location or discussion.
- Approximate date and time.
- The participants involved, if known.
- Any relevant evidence or links.
- Any other context that may help the maintainers understand the situation.

Reports will be handled as confidentially as practical.

---

## Enforcement

The maintainers will review reported incidents and determine appropriate action based on:

- The nature and severity of the behavior.
- Whether the behavior is repeated.
- The impact on other participants.
- Relevant project context.

Possible actions include:

1. Private warning.
2. Request to stop or correct the behavior.
3. Removal of inappropriate content.
4. Temporary restriction from project participation.
5. Permanent restriction from project participation.

Serious incidents may result in immediate restrictions.

---

## Scope

This Code of Conduct applies to project participation, including:

- GitHub issues
- Pull requests
- Discussions
- Code reviews
- Documentation contributions
- Community interactions directly associated with the project
- Official project communication channels
- Events or spaces where participants are representing the WaysNX UI Kit project
